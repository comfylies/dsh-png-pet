# 第二阶段：主动联网随机聊聊

## 背景与第一阶段边界

第一阶段的随机聊聊只在用户已经开启功能、配置目标工作区，并点击桌宠的邀约气泡后才联网。气泡本身使用本地固定邀约文案，不包含任何未经检索的新闻、天气或事实性摘要；点击后在桌宠对话窗口中发起一次受限的“查阅”请求。

第二阶段才考虑在气泡显示前主动检索，并由 AI 根据结果生成第一句话。本文件是第二阶段的需求与简要方案，不授权实现后台检索。

## 目标

- 让已明确授权的用户获得更有时效性的主动话题，例如本地天气、当天新闻或科技见闻。
- 气泡中的事实性内容必须可追溯到近期网页来源；完整答案、检索状态和来源都在对话窗口展示。
- 后台运行不得发送用户输入、会话历史、文件路径、授权信息或任何凭据；只允许为已开启的话题类别发送最小查询词。

## 用户设置与同意

所有项目默认关闭，并需要单独确认：

1. `允许桌宠在后台预先检索`：确认后才可启用本阶段；说明这会在桌宠空闲时访问网页，并可能消耗模型和工具配额。
2. 话题类别：新闻、天气、科技/见闻分别选择。天气必须由用户自行指定城市，不能推断、读取或上传位置。
3. 展示频率、静默时段、每日上限和每类冷却时间；默认不超过每日 3 次。
4. 来源策略：仅允许用户可见的公开网页检索；气泡不显示长摘要、链接或网页原文，进入对话窗口后显示来源与检索时间。

关闭总开关、撤回联网同意、删除天气城市或移除全部话题类别时，应立即取消尚未开始的计划任务，并清除仅在内存中的候选结果。

## 行为要求

- 仅在桌宠空闲、对话窗口关闭、没有进行中的桌宠请求、未处于静默时段且未超过限额时启动。
- 每次只检索一个随机选中的类别；查询和结果只在内存中保留到展示、过期或关闭 Helper，不写日志、文件或设置。
- 新闻、见闻等内容必须有明确的检索时间；过期、来源不足或模型未能给出可验证结论时，降级为第一阶段的本地邀约文案，不展示猜测性事实。
- 气泡必须标记为“刚刚查阅”，并以“点击查看来源和详细聊聊”为操作提示。用户不点击时不把答案写入任何 DSH 会话。
- 点击后打开既有对话窗口，展示检索时间与来源列表，再继续普通多轮聊天；用户可停止当前生成。

## 安全与质量要求

- 网页和搜索结果视为不可信输入：不得把其中的指令当作系统指令或执行指令；只抽取回答所需事实与链接。
- 不将网页正文、工具参数、工具结果、路径、Cookie、授权头或 API Key 经 Helper JSON Lines 转发。Helper 只接收短摘要、可显示来源标题/URL、固定状态和最终可见回复。
- 事实性气泡应优先包含来源数和时间，而非夸张或绝对化结论。无法验证时宁可不打扰。
- 要区分“用户点击后检索”和“后台预检索”的使用量、失败率、撤回授权和限额命中；诊断仅记录固定类别，不记录查询词、文本或来源内容。

## 简要实现方案

1. 在 Host 增加 `ProactiveResearchScheduler`：根据持久化设置、空闲状态、限额和冷却时间决定是否排队；它不接触会话正文。
2. 通过 DSH 已授权的网页工具执行最小化类别查询。该能力应封装为受限接口，允许的类别、城市和最大结果数均由 Host 校验。
3. 增加内存态 `ResearchCandidate`（类别、生成时间、短摘要、可显示来源、过期时间），并向 Helper 发送严格受限的候选气泡协议。
4. Helper 将候选内容渲染为可点击气泡；点击才把候选内容绑定到一个目标工作区中的对话会话。关闭/超时/撤回授权时清空候选。
5. 为调度、授权撤回、过期降级、来源缺失、网页提示注入、协议字段上限和“未点击绝不创建会话”添加单元及集成测试。

## 非目标

- 不自动代表用户发表评论、发送消息、下单或执行网页操作。
- 不读取屏幕、浏览历史、地理位置或私人数据来生成话题。
- 不以后台检索结果替换用户已经进行中的会话或默认会话。
