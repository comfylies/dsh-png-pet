# DSH PNG 桌宠：Windows MVP 项目需求书

## 1. 项目定位

这是一个仅面向 Windows 10/11 x64 的 DeepSeek Harness（DSH）插件。它不是独立聊天应用：入口、会话、模型配置和生命周期都属于 DSH；插件将 DSH 的真实 Agent 事件映射为透明 PNG 桌宠的动画与简短状态提示。

用户日常只看到桌宠和系统托盘，不需要打开本项目的聊天页或设置页。DSH Host 可通过 `dsh web --no-open` 在后台运行而不打开浏览器；用户只有主动选择“打开 DSH”时才进入 DSH WebUI。

目标是做出轻量、可信、不会干扰工作的 Agent 状态伴侣，而不是第二个 DSH 前端或养成游戏。

## 2. MVP 目标

- DSH 启动并启用插件后，自动显示桌宠；DSH 正常退出后，桌宠自动退出。
- 桌宠只依据 DSH 的真实 Session/Agent 事件切换 PNG 动画和状态文案。
- 用户能通过托盘和桌宠右键菜单显示、隐藏、调整大小、减少动态效果、打开 DSH 和本次关闭桌宠。
- 用户能拖拽桌宠位置；应用重启后保留位置。
- 插件不读取或保存模型 API Key，不直接调用模型 API，不创建额外网络端口。

## 3. 范围

### 本期包含

| 模块 | 需求 |
|---|---|
| DSH 插件 | TypeScript/Node.js DSH Host 插件；订阅 `session/event` 与 `session/disposed`，管理配置和 Helper 生命周期 |
| 桌宠 Helper | C# WPF 自包含 Windows 可执行文件；透明、无边框、置顶、跳过任务栏、可拖拽 |
| 状态显示 | idle、thinking、working、waiting、success、error、disconnected 七种状态；PNG 帧动画与简短气泡文案 |
| 跨进程通信 | 插件与 Helper 仅通过 stdin/stdout 的 JSON Lines 双向通信，不使用 HTTP、WebSocket 或本地端口 |
| DSH 设置 | 启用开关、角色大小、减少动态效果、是否响应子 Agent；由 DSH 设置服务持久化 |
| 本地数据 | Helper 仅保存窗口位置和临时关闭标记；DSH 负责插件设置，不另存会话记录 |
| 托盘与菜单 | 显示/隐藏、大小档位、减少动态效果、打开 DSH、本次关闭；退出 DSH 时自动清理 |

### 本期不包含

- 独立聊天窗口、会话管理、模型选择（桌宠会话框仅显示选定会话的最近对话：用户文本消息与助手最终文本回复，不显示 reasoning、工具细节、文件路径或凭据）
- API Key 的输入、保存、删除、传递或直接请求 DeepSeek API
- React、Vite、Tauri、WebView、Electron 或独立安装包
- 语音输入、TTS、唇形同步、屏幕读取、自动操作电脑、联网工具调用
- Linux、macOS、WSL2、开机自启、多宠物、养成数值、投喂、角色编辑器
- 全像素点击穿透；MVP 仅通过紧贴角色内容的窗口尺寸减少遮挡

## 4. 架构与生命周期

```text
DSH Host（后台，可不打开浏览器）
  └─ TypeScript DSH 插件
      ├─ 订阅真实 Session/Agent 事件
      ├─ 状态归约与多 Session 优先级选择
      ├─ 读取 DSH 插件设置
      └─ stdin/stdout JSON Lines
          └─ C# WPF pet-helper.exe（唯一可见界面）
              ├─ 透明 PNG 桌宠与状态气泡
              ├─ 拖拽、右键菜单、托盘
              └─ 位置与临时关闭状态
```

1. DSH 完成插件加载后，插件读取设置；启用时启动随 npm 包发布的 `pet-helper.exe`。
2. Helper 启动后通过 `ready` 消息确认；插件发送当前配置和初始 `idle` 状态。
3. 插件只观察 DSH 事件，归约出状态后向 Helper 发送 `state`、`task` 或 `config` 消息。
4. DSH 停止、插件被禁用或插件卸载时，插件发送 `shutdown` 并等待 Helper 退出；超时后才终止子进程。
5. Helper 意外退出时，插件记录不含会话内容的诊断信息，并以有限次数退避重启；用户选择“本次关闭”后，本次 DSH 运行期间不自动重启。

## 5. 状态与动画约定

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| idle | 没有需要展示的活动顶层 Session | 新任务或 Agent 活动开始 |
| thinking | DSH 正在组织请求、推理或处理非工具结果 | 开始工具工作、等待、完成或异常 |
| working | DSH 正在执行搜索、读取、修改、命令或测试等工作 | 回到 thinking、等待、完成或异常 |
| waiting | DSH 明确等待用户确认、输入或恢复任务 | 用户继续任务、任务结束或异常 |
| success | 顶层任务正常完成 | 成功动画播放一次后回 idle，或出现新任务 |
| error | 顶层任务异常结束，或工具/任务失败 | 错误动画短暂停留后回 idle，或用户重试 |
| disconnected | Helper 尚未收到插件握手、插件通信中断或 DSH 正在关闭 | 收到有效握手和状态，或 Helper 退出 |

多 Session 同时运行时，默认只选择最需要用户注意的顶层 Session：`waiting > error > working > thinking > success > idle`。子 Agent 默认不参与竞争；用户在 DSH 设置中启用后才参与，并低于同级顶层 Session。

状态必须来自 DSH 可验证事件和结构化待办。缺少真实待办数据时，只显示阶段描述，不虚构百分比或完成进度。

## 6. 桌面交互与设置

- 拖动：按住角色可见区域移动窗口；位置以当前屏幕工作区坐标保存，下一次启动时校正到可见屏幕范围内。
- 右键菜单：显示/隐藏、角色大小、减少动态效果、打开 DSH、本次关闭。
- “本次关闭”：关闭 Helper 并抑制当前 DSH Host 生命周期内的重启；下次 DSH 启动时恢复。
- “打开 DSH”：仅显式触发时打开 DSH WebUI；插件绝不在启动时自动打开浏览器。
- DSH 设置页负责持久化“启用桌宠、角色大小、减少动态效果、是否响应子 Agent”。托盘菜单的临时显示/隐藏不改变 DSH 的启用开关。

## 7. 安全与隐私要求

- 插件与 Helper 不读取、保存、显示或记录模型 API Key、授权头或 DSH 凭据。
- 插件不直接向 DeepSeek 或任何外部服务发请求；模型调用完全由 DSH 处理。
- 不截图、不监听键盘、不读取其他应用窗口、不扫描文件内容、不修改 DSH Session。
- 插件不创建额外监听端口；与 Helper 的通信仅限受父进程控制的标准输入输出。
- 桌宠会话框只显示用户自己的文本消息与助手最终文本回复（由 DSH 会话日志脱敏提取）；不显示 reasoning、工具调用、参数、文件路径或凭据。
- 日志只记录生命周期、协议版本、状态种类和错误类别；不得记录工具参数、文件路径或会话正文原文。
- Helper 的位置文件只包含窗口坐标、缩放和本次关闭标记。

## 8. 非功能要求

- 支持 Windows 10/11 x64；发布的 Helper 使用 .NET 10 LTS 自包含方式打包，终端用户无需为本插件额外安装 .NET、Python、Rust 或另行启动 Helper。
- DSH 及其 Node.js 运行环境是插件运行前提，不属于本插件重复安装或管理的范围。
- 闲置时保持低频动画；开启减少动态效果后使用静态帧或低频动画。
- 插件事件处理异常、Helper 崩溃或 DSH 关闭均不得阻塞 DSH 的其他插件、Session 或正常退出。
- DSH Host 未启动、插件未启用或通信失败时，Helper 不应以孤儿进程持续运行。

## 9. 验收标准

1. 在 Windows 10/11 x64 上通过 `dsh plugin --profile web add <package>` 安装后，运行 `dsh web --no-open` 不会打开浏览器，且启用插件时桌宠出现。
2. 桌宠的思考、工作、等待、成功、错误和空闲状态由真实 DSH 事件驱动；无事件时不会伪造进度。
3. 多个 Session 同时运行时，显示状态符合 `waiting > error > working > thinking > success > idle` 的顶层优先级；默认忽略子 Agent。
4. 拖拽、显示/隐藏、大小调整、减少动态效果、打开 DSH和本次关闭菜单均可用；重启后位置和 DSH 持久设置仍有效。
5. 禁用插件、退出 DSH 或卸载插件后，Helper 自动退出且不遗留运行进程。
6. 在设置、Helper 数据、日志、stdout/stderr 中检查不到 API Key、授权头、提示词、回复、工具参数或会话内容。
7. 普通 Windows 用户在已可运行 DSH 的前提下，无需为本插件额外安装 .NET、Python 或 Rust，即可使用随插件发布的 Helper。
