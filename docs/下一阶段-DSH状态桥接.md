# 下一阶段：DSH 状态桥接

## 目标

让桌宠只依据 Harness 的真实 Session/Agent 活动切换可见状态。第一版优先显示简短、安全的状态气泡；不要求先完成完整帧动画资源。

## 用户可见行为

| 桌宠状态 | 含义 | 第一版表现 |
| --- | --- | --- |
| idle | 没有活跃顶层任务 | 无气泡，维持当前睡眠形象。 |
| thinking | Agent 正在组织或处理模型结果 | “思考中…”气泡。 |
| working | Agent 正在执行工具、命令、读写或测试 | “工作中…”气泡。 |
| waiting | Harness 正在等待用户确认或输入 | 更醒目的“等待你的操作”气泡。 |
| success | 顶层任务正常完成 | 短暂“已完成”气泡，然后回到 idle。 |
| error | 顶层任务失败 | 短暂“发生错误”气泡，然后回到 idle。 |
| disconnected | Helper 未握手、通信失效或 DSH 正在关闭 | “未连接”提示，随后由生命周期策略关闭。 |

不显示提示词、模型回复、命令参数、文件路径、API Key 或会话正文。

## 架构

1. 先在当前安装的 DSH 版本中读取并记录可用的公开 Session/Agent 事件及载荷结构；不能依据猜测的事件字段实现。
2. TypeScript 增加纯函数 CompanionReducer：输入已脱敏的事件事实，输出 Session 状态、事件序号和当前展示状态。
3. 多 Session 同时活跃时只选择一个顶层状态：waiting > error > working > thinking > success > idle；子 Agent 默认忽略。
4. 协议升级为携带显式安全载荷的版本：Host 向 Helper 发送 state（状态枚举、短标签、事件序号）和 config（缩放、减少动态效果等）。旧 Helper 收到不兼容协议时明确进入 disconnected，不静默误显示。
5. WPF 只渲染状态枚举和固定短标签；未知字段、超长文本和未知状态一律回退为 disconnected。

## 范围

本阶段包含事件调研、状态归约、状态气泡、协议校验、优先级和单元/集成测试。

本阶段不包含七套 PNG 帧动画、声音、模型内容展示、DSH 设置页面、打开浏览器、联网服务或新的本地端口。

## 验收标准

- 使用录制的脱敏 DSH 事件流，能稳定覆盖七种桌宠状态。
- 乱序、重复、未知和已释放 Session 事件不会让插件抛异常或改变其他 DSH 功能。
- 多任务时严格遵守优先级；默认不由子 Agent 抢占桌宠状态。
- Helper 只收到状态枚举与固定短标签；测试和日志中不出现会话正文或凭据。
- 退出 DSH、禁用插件或关闭 Helper 时，不遗留桌宠进程。

## 实施顺序

1. 调研当前 DSH 的事件 API，并写出事件适配器的输入夹具。
2. 测试驱动实现 CompanionReducer 与优先级选择。
3. 扩展 JSON Lines 协议并完成 TypeScript 与 C# 双端校验。
4. 实现 WPF 状态气泡和超长/未知状态回退。
5. 在独立 Helper、模拟 DSH 事件流和真实 web profile 中分层验收。

状态桥接稳定后，再单独设计“PNG 状态动画与减少动态效果”阶段。
