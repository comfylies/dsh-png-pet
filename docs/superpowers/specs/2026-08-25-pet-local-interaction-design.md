# PNG 桌宠本机交互设计

## 目标

为当前独立运行的 Windows WPF Helper 提供日常桌宠交互：左键拖动、右键菜单、显示/隐藏、缩放、重置和彻底关闭。该阶段不依赖 DSH 或网络服务。

## 交互模型

角色窗口通过左键按住并拖动移动；拖动结束时保存窗口左上角坐标。右键显示 WPF 原生 `ContextMenu`，菜单包含：隐藏、缩放子菜单（75%、100%、125%、150%）、重置大小与位置、关闭桌宠。

“隐藏”只将窗口设为不可见，Helper 进程继续运行。隐藏后，在 Windows 系统托盘保留一个轻量图标；其菜单提供“显示桌宠”和“退出桌宠”，双击图标也显示窗口。这是隐藏状态下唯一的恢复入口，避免用户只能打开任务管理器。托盘只负责本机窗口的显示与退出，不连接 Harness。

“关闭桌宠”调用 WPF 正常关闭路径，结束 Helper 进程。若它由未来 DSH 插件托管，插件会通过已有退出事件知道进程已停止；本阶段不实现重启或“本次关闭”抑制策略。

## 状态与持久化

`PetWindowStateStore` 只保存非敏感 JSON：窗口 `left`、`top` 和 `scale`。文件位于当前用户的 LocalApplicationData 下 `DshPngPet/window-state.json`。读到无效、缺失或越界数值时使用默认值：缩放 100%，窗口居中；写入失败不会阻止交互或退出。

缩放只改变窗口宽高（基准 220 × 220），图片保持 `Uniform` 拉伸。重置将缩放设为 100%，并调用 `WindowStartupLocation.CenterScreen` 的等价计算将窗口置于当前工作区中心。

## 错误处理与测试

窗口坐标、缩放范围和状态 JSON 解析放在独立的无 UI 类中，使用 C# 单元测试覆盖有效恢复、无效状态回退、缩放限制与重置。WPF 窗口代码只将鼠标和菜单事件委托给该类。

发布回归测试保持“启动后发送 ready”的检查，确保新增交互不影响 Helper 协议握手。手工验收覆盖拖动、每个缩放档位、隐藏、重置和关闭。

## 范围限制

本阶段不引入快捷键、动画状态、点击穿透、DSH 设置同步或打开 DSH。系统托盘仅限显示、隐藏恢复与退出，不扩展为 Harness 控制台。
