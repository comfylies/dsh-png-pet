# 外置人物形象与 GIF 导入设计

状态：已按用户后续指令实现于本地 v0.2.11；JSON Lines 保持 v17。下文记录设计与实现边界，用户操作说明见 `docs/外置人物使用说明.md`。

## 1. 目标与当前事实

提供「右键桌宠 → 人物形象」入口，支持添加、预览、切换和移除不同角色。新增素材独立保存在本机，不进入插件 tgz 或 Helper EXE；首次升级获得此功能后，添加和切换角色均不需要重新编译、安装插件或重启 DSH。

设计前基线（2026-09-10）：package.json 为 0.2.10，JSON Lines 为 v17，内置动画清单为 v4。PetHelper.csproj 将 PNG 和清单嵌入程序；PetAnimationPlayer 仅通过 pack URI 加载图片。此次在该基线上增加外置人物与逐帧时长，保留内置资源和 v4 清单。

保留当前内置角色作为默认和故障回退。仅新增角色外置；移出已有内置动画以进一步缩小安装包属于另一个变更。

## 2. 用户体验

人物形象窗口是 Helper 所属的 WPF 窗口，显示静态缩略图、名称和当前选中标记。只对选中项播放预览，避免整个人物库同时解码动画。

| 操作 | 行为 |
| --- | --- |
| 添加 GIF / PNG | 本地文件选择 → 输入角色名称 → 预览、调整头顶锚点与脚底基线 → 导入。默认名称为「新人物」，不自动保存原文件名。 |
| 添加角色目录 | 选择含 character.json 的目录，校验其声明的素材，预览后导入。 |
| 使用此人物 | 预加载新角色当前状态首帧，成功后一次性替换；保留桌宠位置、缩放、对话窗口和当前会话。 |
| 移除 | 仅删除本项目已导入副本，明确提示；当前角色先切回默认角色，再移除。内置角色不可移除。 |
| 恢复默认 | 立即使用内置角色，不删除其他角色。 |

一个 GIF 即可成为角色：所有状态共用其 idle 动画，真实工作状态仍由气泡和文字即时表达。若需要思考、工作、成功等不同动作，导入多状态角色目录。素材只改变外观，不改变模型、Agent、会话目标或系统提示词。

原图带背景时原样展示，不自动抠图。GIF 支持调色板透明色，细腻半透明边缘仍优先使用 PNG 序列；导入面板以棋盘格显示透明效果。

## 3. 外置存储与所有权

建议固定目录如下（运行时从 LocalApplicationData 获取根目录）：

```text
%LOCALAPPDATA%/DshPngPet/Characters/
  selection.json                 # 仅保存版本和 selectedCharacterId
  library/<generated-id>/
    character.json               # 校验、重写后的角色元数据
    frames/<generated-clip-id>/  # 规范化 PNG 帧
  staging/<generated-id>/        # 导入中的临时目录
```

- Helper 只导入用户明确选择的本地素材；输入路径只在选择和读取期间短暂存在于内存，不进入设置、JSON Lines、日志或错误文本。
- 采用复制导入；完成后不依赖原文件。生成随机角色 ID 和内部文件名，不沿用来源路径、文件名或来源清单中的角色 ID。
- 写入本地的内容仅限角色图片、必要动画元数据、用户指定的角色名称与选择记录，不含对话、历史、附件、工具内容或 DSH 数据。
- 导入时去除不需要的图片元数据，重新编码生成 PNG；不保留原 GIF、来源目录结构、注释或脚本。
- staging 全部校验成功后在同卷内提交为新 library 项；取消、失败不改变现有角色。清理只针对经过边界验证的本项目 staging 子目录。
- 插件升级和重装不清理 Characters；移除角色由用户明确操作。第一版按当前 Windows 用户共享角色和选择，不承诺多 profile 独立外观。多 Helper 进程启动时读取最后一次选择，运行中的其他窗口不主动同步；写入须串行化并原子替换。

本次已同步修订 AGENTS.md 和项目需求书，将「Helper 仅保存窗口布局」扩展为「布局及用户导入的纯展示资源/选择」；只允许用户选定文件和导入库的受控读取、内部相对资源标识，仍禁止收集 DSH、对话和工具中的路径。

## 4. 角色目录格式（首版）

外置角色使用独立的 characterFormatVersion: 1，不复用或放宽现有内置 v4 清单解析器。最小目录只需 character.json 和 idle.gif：

```json
{
  "characterFormatVersion": 1,
  "name": "小狐狸",
  "statusAnchor": { "x": 0.5, "y": 0.12 },
  "baseline": 0.95,
  "actions": {
    "idle": { "type": "gif", "file": "idle.gif" },
    "thinking": { "type": "gif", "file": "thinking.gif" },
    "working": { "type": "png-sequence", "frames": ["working/001.png", "working/002.png"], "frameDurationMs": 100 },
    "success": { "type": "png", "file": "success.png" }
  }
}
```

说明：上例是多状态例子；最小版本删除 idle 以外的动作与文件即可。

- 版本、字段、类型、重复 JSON 键全部严格校验；未知版本或字段拒绝导入。名称 1–40 字符，不允许控制字符，不作为文件名或富文本解释。
- 动作键只接受现有十种：idle、thinking、working、thinking-working、responding、waiting、question、success、error、disconnected。idle 必须存在且可解码。
- 每个动作恰好一种素材形式；gif/png 只允许 type、file；png-sequence 只允许 type、frames、frameDurationMs。锚点 x/y 与 baseline 为有限的 0–1 数值。
- 首版每个状态一个循环 Clip；静态 PNG 持续显示。GIF 自带有限循环次数不决定状态持续时长，UI 提示「按当前状态循环播放」。不推断 GIF 的某一段是思考或成功。
- 外置角色缺少任何状态均回退该角色 idle，不把内置角色的某个动作混入外置人物。内置角色仍按原 v4 program/transition 播放。
- 多状态素材使用相同逻辑画布；PNG 序列帧尺寸必须相同。基线与头顶锚点按画布归一化保存，预览可调整；不承诺自动识别人像。换角色时保持脚底屏幕位置，随后按显示器工作区夹紧窗口位置。
- 外置多 Clip、enter/transition 编排留给后续角色格式版本；首版不增加素材编辑器、ZIP 导入或在线角色商店。

## 5. GIF 实现方案

采用「导入时解码并规范化为 PNG 帧，播放时复用统一引擎」。用户直接提供 GIF，无需手动拆帧；生成文件只留在本机外置库，不进入发布包。

WPF 提供 GifBitmapDecoder，可从流访问帧和元数据；WIC 提供 Delay、Disposal、透明色与图像偏移等查询字段。实现必须据此合成完整逻辑画布，不能把每个差分帧当成独立整图播放。[Microsoft GifBitmapDecoder 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.gifbitmapdecoder?view=windowsdesktop-10.0)、[WIC 元数据查询](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-native-image-format-metadata-queries)。

具体处理：

1. 在解码前检查文件签名、逻辑画布、帧数及输入配额；在 Helper 的后台工作线程逐帧解码、合成、缩放和写入，支持帧间取消，UI 保持响应。不得一次性缓存所有全尺寸帧。
2. 正确处理局部帧偏移、透明色，以及 disposal 的保留、恢复背景、恢复上一帧语义；未知处置方式拒绝。GIF 背景不能一律强制透明，须通过透明/不透明样例验证。
3. GIF Delay 按百分之一秒换算。有效延迟保留为逐帧时长；缺失或为零统一使用 100 ms，小于 20 ms 归一为 20 ms 并在预览中提示；大于 10 秒的单帧延迟拒绝。PNG 序列继续沿用 16–1,000 ms 固定间隔。
4. 内部 ResolvedClip 增加可选逐帧时长数组，长度须与 Frames 完全一致；现有内置 Clip 继续使用 FrameDurationMs。规范化磁盘清单使用独立明确版本，校验生成 ID、固定相对帧标识、尺寸和时长，不信任文件曾由本程序生成。
5. PetClipPlayback 返回当前帧时长；一次播放的末帧必须停留完整时长后再发 Completed，单帧 once 也遵守此规则。当前实现在到达末帧时即完成，需要测试先行修正并回归内置转场。
6. 减少动态效果时显示稳定首帧并停止计时；恢复时不补播导入、切换或关闭动态效果期间错过的动作。

## 6. 加载与切换架构

新增 CharacterLibrary（目录、选择记录、导入、删除）、CharacterManifest（来源格式）、CharacterFiles（受控文件访问）、GifFrameImporter（解码合成）、CharacterWindow（人物管理 UI）。选择记录通过库的同一文件锁串行化，不另建存储服务。

PetAnimationPlayer 保留原内置加载器，新增可选 CharacterAssetSource 读取选中角色根目录内的规范化资源。PetStateAnimationCoordinator 接受本地程序解析回调，使内置清单和外置动作共用编排器，无需扩展通信协议或改变 DSH 状态输入。

切换先准备新资产源与首帧，再在 UI 线程替换整个播放器上下文；旧转场队列取消，以最新真实状态启动新角色。缓存键包括角色 ID 和修订标识，不能只使用 idle/default 等 Clip 名。异步准备使用代次标识，快速连点时过期结果不得覆盖最新选择。提交后释放旧图片、句柄和计时器订阅。

切换准备失败则保留原角色；已在使用的角色资源损坏或被移除，则回退内置角色并显示一次固定提示。选择记录丢失、损坏或指向不存在 ID 时同样回退。状态气泡、取消与审批响应不得依赖素材加载成功。

首版人物管理和选择记录都归 Helper，因此无需新增 JSON Lines 字段，不更改 DSH 设置与网页设置页。后续若要求网页也能切换人物，再设计纯 ID 协议并按当时版本升级，同步修改 TS/C# 解析器、调用点和测试；不通过协议传路径、图像或清单。

## 7. 外部输入与资源限额

以下为首版建议默认值，应在 Windows 实测后定稿：

| 项目 | 建议限制 |
| --- | --- |
| 清单 | 64 KiB，JSON 深度不超过 8 |
| 单图片文件 / 单角色输入总量 | 20 MiB / 100 MiB |
| 原始逻辑画布 | 每边不超过 2,048 px；帧矩形不得越界 |
| 动作 / 单 Clip / 单角色 | 最多 10 个动作 / 240 帧 / 1,024 帧 |
| 总解码工作量 | 每角色累计完整画布像素不超过 256 百万，含 GIF 合成帧 |
| 导入结果 | 等比缩小至最长边不超过 512 px，不放大小图；每角色落盘不超过 256 MiB |
| 角色库 | 最多 50 个外置角色、总量 1 GiB；包括暂存导入，超限不自动删除旧角色 |
| 运行缓存 | 按解码后字节数设 64 MiB 上限，包含预览与切换预加载；进程总内存另作实测 |

只读取清单引用的 PNG/GIF，按内容签名校验格式，不按扩展名选择任意系统解码器。帧标识只允许受限相对形式，拒绝绝对路径、..、空段、反斜杠、冒号/ADS、设备名、URL 与 UNC/网络位置。

对导入源和库路径逐层检查重解析点，拒绝符号链接/junction；在实际读取时复核最终文件位置，不能只做字符串前缀判断。源文件读入受限快照后再校验和解码，避免校验后替换。来源目录中未声明的文件完全不读取、不复制。

不执行 EXE、脚本、DLL、XAML 或清单中的命令；不下载素材，不启动额外服务或监听端口。捕获可恢复的导入/解码异常，只显示固定错误码或固定中文提示，不输出原始异常及路径。限额与后台线程降低卡顿和内存风险，但不等同于原生图像解码器的进程隔离；首版保持单 Helper 架构。

## 8. 实施顺序与验收

实现前阅读现有长 Clip、状态编排及转场设计，先补充对应测试，再实现：

1. 外置目录、安全校验、PNG 导入与角色选择；验证一次性切换、失败保留原角色、重启恢复和边界外文件不被读取/删除。
2. GIF 规范化与逐帧时长；使用最小专用样例覆盖不同 Delay、透明色、局部更新、disposal 0/1/2/3、有限循环、损坏文件、超限和取消。验证末帧停留、单帧 once 和已有 enter/transition 的完成时机。
3. WPF 人物窗口、多状态目录导入、锚点/基线预览与减少动态效果。验证快速切换无旧帧闪回、拖动/缩放/会话/审批持续正常、后台导入不阻塞流式对话。
4. 包验证：在测试外置目录加入专用样例，分别检查 tgz 文件清单和 EXE 资源，确认样例与用户库未进入产物。禁止发布脚本扫描或复制 LocalApplicationData；保持 .NET 10 自包含单文件及 IncludeNativeLibrariesForSelfExtract=true。
5. 运行 npm test、dotnet test pet-helper.Tests/PetHelper.Tests.csproj --no-restore、npm run build:helper、npm run test:package、npm run package:release。资源和生命周期改动执行完整序列；发布按项目规范递增版本，安装仍需重启现有 DSH 才加载新功能。

验收结果应包括：导入单个 GIF 后立即作为人物使用；不同状态素材随真实活动切换；缺状态保持该人物 idle；插件升级后外置人物仍可用；新增人物不增加发布包中的角色素材；导入和播放期间无项目网络请求、无路径/会话内容落入日志。

实现补充：外置图像以透明边距补齐方形画布，便于沿用 WPF 的归一化锚点。运行播放器缓存上限 49 MiB，预览缓存上限 8 MiB，切换只预载当前首帧后释放旧缓存；缩略图单独缩小至 64 像素，总缓存预算控制在 64 MiB 内（不含解码器、WPF 合成器及进程其他内存）。暂存导入正常取消时清理，强制结束留下的 staging 文件仍计入配额，不自动删除可能属于另一 Helper 的导入。
