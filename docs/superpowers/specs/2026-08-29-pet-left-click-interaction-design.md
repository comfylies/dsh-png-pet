# 桌宠左键交互设计

## 目标

让人物窗口的左键行为符合桌宠的直接交互预期：轻点角色即可进入对话，而明确的拖拽仍可平滑移动人物。现有实现把每次左键按下立即交给 Windows 原生拖动，只有双击才切换对话；这使单击没有交互反馈，并会让用户为了打开输入框而猜测双击入口。

本设计只调整 WPF Helper 的本地鼠标语义，不改 JSON Lines 协议、Harness 会话逻辑、回复内容或任何持久化字段。

## 用户交互

| 操作 | 结果 |
| --- | --- |
| 在人物上短按并释放 | 若对话隐藏，显示对话、按现有规则放置并聚焦输入框；若已显示，将其置前并聚焦输入框。 |
| 左键按住后移动超过 Windows 系统拖拽阈值 | 移动人物窗口；不会打开或关闭对话。 |
| `Ctrl` + 左键拖拽 | 保留现有联动拖拽：人物移动时，可见的对话窗口以相同位移跟随并保持在可见工作区内。 |
| 双击人物 | 等价于一次“打开/聚焦对话”，不产生第二次切换，也不隐藏对话。 |
| 右键、拖放目录、托盘菜单 | 保持现有行为不变。 |

左键不根据桌宠状态（空闲、思考中、输出中、等待等）改变含义，也不会停止正在生成的回复。停止、隐藏和退出仍由对话窗口与右键/托盘中的明确控件完成，避免误触造成内容或窗口状态变化。

## 手势判定

人物窗口维护一次指针手势状态，而不是在 `MouseLeftButtonDown` 时立刻调用 `DragMove()`：

```text
空闲
  └─ 左键按下 → 候选点击（记录屏幕坐标、当时 Ctrl 状态，并捕获鼠标）
       ├─ 移动距离超过系统水平或垂直拖拽阈值
       │    → 拖拽中（释放捕获，调用原生 DragMove）
       │         └─ 鼠标释放 → 结束拖拽、边界校正、保存位置
       ├─ 未超过阈值即左键释放 → 打开或聚焦对话
       └─ 失去捕获 / 其他按键取消 → 空闲，不触发对话
```

阈值使用 `SystemParameters.MinimumHorizontalDragDistance` 与 `SystemParameters.MinimumVerticalDragDistance`，而不是自定义像素常量，以匹配 Windows 的鼠标、触控板和缩放设置。只要任一方向超过相应阈值，手势就是拖拽；阈值内的轻微抖动仍是点击。

开始实际拖拽时才暂停 `PetAnimationPlayer`，结束后恢复。这样轻点不会中断动画，且继续复用现有原生 `DragMove()` 的无闪烁移动、人物越界校正、位置保存和 Ctrl 联动逻辑。

## 对话窗口语义

`MainWindow` 的现有 `ToggleDialogueWindow()` 改为两个意图明确的方法：

- `OpenOrFocusDialogue()`：隐藏时调用 `ShowDialogue(CurrentRect())`；可见时仅激活窗口并将键盘焦点放到输入框，不重设位置、不重复加载历史。
- `CloseToHidden()`：只由对话窗口关闭按钮和现有明确的隐藏入口调用；左键不再调用它。

`DialogueWindow` 提供一个很小的 `ActivateComposer()` 公开方法，封装 `Activate()` 与输入框聚焦。这样 `MainWindow` 不需要了解或访问对话窗口的 XAML 控件。

首次打开仍由 `ShowDialogue` 使用保存位置或人物旁的智能位置；已打开时的左键只带来焦点，不会把用户手动移动过的对话窗口拉回人物旁。

## 实现边界

修改范围：

- `pet-helper/MainWindow.xaml`：增加人物区域的 `MouseMove`、`MouseLeftButtonUp` 和 `LostMouseCapture` 事件。
- `pet-helper/MainWindow.xaml.cs`：以候选点击/拖拽状态替换“按下即拖动 + 双击切换”；保留现有拖拽结束清理路径。
- `pet-helper/DialogueWindow.xaml.cs`：增加仅用于激活和聚焦输入框的公开方法。
- `pet-helper.Tests/`：为手势判定和可见对话聚焦添加单元测试。
- `test/wpf-layout.test.mjs`：将静态约定从“双击切换”更新为“短按打开/聚焦与系统阈值拖拽”。

不会改动协议类型、Node 桥接、会话选择、动画清单、窗口状态 JSON 格式或发布资源。完成功能后才递增 npm 包版本并按既有流程重新构建、测试、打包和安装。

## 可测试性与验收

将距离判定抽成无 UI 的小型 `PetPointerGesture`（或等价纯函数），使其覆盖：

- 按下后未越过两个阈值的释放判定为点击；
- 水平或垂直任一方向越过阈值判定为拖拽；
- 取消和失去鼠标捕获不触发点击；
- `Ctrl` 状态在按下时锁定，拖拽中途变化不改变本次手势的联动含义。

WPF 测试验证：短按隐藏对话会调用显示与输入框聚焦；短按可见对话只激活、不隐藏、不重放历史；拖拽时不打开对话，结束后仍执行当前的边界校正和位置保存。Node 布局测试验证人物区域声明了完整的三阶段鼠标事件，并使用系统拖拽阈值。

手工验收：在空闲、思考中与输出中各短按一次，确认对话总能打开或取得输入焦点且动画不中断；带微小抖动短按不会移动人物；跨过阈值拖动人物不会打开对话；`Ctrl` 拖动时两窗口仍正确联动；连续双击后对话保持可见且位置不变。

## 风险与缓解

原生 `DragMove()` 是阻塞式窗口移动，因此必须只在越过阈值后开始，并在进入前释放 WPF 鼠标捕获；拖动返回后统一执行现有 `finally` 清理。捕获丢失时清空候选状态，避免窗口失焦、右键或系统操作被误解释为点击。

短按已经打开的对话只聚焦，不切换隐藏，牺牲了一个“快速收起”手势，但避免双击的第二下、连续点击或流式阅读时误关窗口。关闭按钮和右键“隐藏”仍为明确、可发现且可恢复的关闭入口。
