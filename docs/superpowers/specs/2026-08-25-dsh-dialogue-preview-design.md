# DSH 桌宠对话与流式预览设计

## 目标与授权边界

用户可点击桌宠，在其上方的输入气泡中输入消息，并发送给在 DSH 设置中选择的默认会话。用户可选择开启“回复预览”；该设置默认关闭，开启后桌宠流式显示该次桌宠消息触发的助手可见文本。

这是对现有“不得传递提示词或模型回复”边界的用户授权例外，且只适用于以下两类短暂内存数据：用户在桌宠输入框主动提交的文本，以及用户显式开启预览后、该请求对应的助手可见文本。两者不得写入日志、文件、DSH 插件设置、Helper 位置文件或诊断输出；不得传递 API Key、授权信息、系统提示词、推理字段、工具参数、工具结果、路径或任何其它 Session 正文。

## DSH 会话选择与设置

DSH 设置增加“默认会话”选择器。它使用 DSH 持久会话服务列举全部已有会话，但只读取内部会话标识及创建排序所需的非内容元数据。设置 UI 为每次列表渲染生成“会话 1”“会话 2”等安全别名，绝不显示标题、cwd、消息、路径或原始会话标识。

选择器保存的只是 DSH 设置中的内部会话标识；该标识不经 JSON Lines 发送给 Helper。桌宠发消息时，Host 优先取得对应的 live Agent；若会话仅已持久化而尚未运行，则调用 DSH 的标准恢复流程。恢复或投递失败、或默认会话已删除时，Host 清空该设置并向 Helper 发送固定错误码，Helper 只显示“请在 DSH 设置中选择会话”。

## 桌宠交互

左键点击桌宠时，在形象上方显示一个锚定输入气泡，标注固定的“发送到已选会话”。未选择默认会话时，发送按钮禁用并显示前述固定提示。Enter 发送，Shift+Enter 换行，Esc 或关闭按钮放弃并立即清空输入框。一次只允许一个正在发送的桌宠请求；Agent 忙碌时使用 DSH 的普通 follow-up 队列，界面显示固定“已排队”，不强制打断正在进行的任务。

回复预览默认关闭。开启时，输入气泡变为可滚动的预览气泡，显示当前桌宠请求所触发的助手可见文本流。它只保留一条当前回复的滚动缓冲；关闭预览、切换默认会话、发送下一条、取消输入、Helper 退出、Host 断开或会话失效时立即清除。预览不会显示聊天历史，也不会接收并显示用户从 DSH WebUI 发起的其它轮次。

## 可调预览长度

DSH 设置新增“回复预览长度”，为 `80` 至 `2000` 的整数，默认 `480`。该值在 Host 和 Helper 两端都重新校验，`2000` 为不可绕过的硬上限。预览缓冲仅保存最近 `N` 个字符，其中 `N` 为已校验的设置值；WPF 气泡以有限高度滚动显示该缓冲。长度变化立即裁剪当前缓冲，关闭预览立即清空缓冲。

## 事件筛选与数据流

```text
WPF 输入气泡
  -- 受限用户输入 --> Host 插件
  -- DSH follow-up --> 已选 Agent / 会话
  -- 仅该请求的可见文本片段（预览开启） --> Host 插件
  -- 受限回复预览 --> WPF 气泡
```

Host 只在预览开启后处理与该桌宠请求关联的 `assistant/chunk` 可见文本增量；未知 chunk 形状、工具调用、推理、非文本块和与该请求不匹配的 turn 一律丢弃。Host 用 DSH 的 turn 关联字段将预览限定到本次提交，不依赖消息正文作匹配。每次更新只保留经过字符上限裁剪后的滚动缓冲，且错误边界只记录固定错误类别。

## 协议 v4

Host 与 Helper 同步升级至 JSON Lines v4，行长上限为 `4096` 字符，任何文本字段最大 `2000` 字符。既有 `hello`、`config`、`state`、`shutdown`、`ready`、`closed` 均带 v4；状态气泡的固定枚举规则保持不变。

新增的严格消息如下，字段名只表示协议结构，文本本身绝不写入测试快照、日志或错误信息：

- Helper → Host：`input`，含单调 `requestId` 与用户文本。拒绝空白文本、超过上限、未知字段或重复/倒序请求号。
- Host → Helper：`conversation-config`，含已校验的 `previewEnabled` 与 `previewMaxChars`；不含会话标识。
- Host → Helper：`input-status`，只含 `requestId` 与固定种类 `queued`、`sent`、`no-default-session`、`session-unavailable` 或 `rejected`。
- Host → Helper：`reply-preview`，含 `requestId`、经过裁剪的助手可见文本和 `completed` 布尔值。仅当预览开启、请求关联有效、文本合法时发送。
- Host → Helper：`clear-preview`，含请求号或固定清除原因，不含文本。

TypeScript 与 C# 两端都必须对 kind、精确字段集合、版本、整数范围、枚举、布尔值和文本长度做一致校验。无效 Helper 输入不得进入 DSH；无效 Host 消息使 Helper 显示 `disconnected` 并有序关闭。协议处理或日志中不得回显原始输入或回复。

## 测试策略

- TypeScript：先为设置选择、会话别名/内部标识隔离、默认会话失效、live/恢复投递、忙碌 follow-up 排队、清理时机和 turn 关联写失败测试。
- 协议：测试 v4 的严格消息校验、长度边界、未知字段、错误码和预览关闭时绝不发送文本；测试输出只断言长度、种类和请求号，不包含文本内容。
- C#：测试输入气泡的固定状态、长度裁剪、关闭清除、滚动预览、无默认会话提示及非法消息回退，不在断言中保留原始文本。
- 集成：fake Helper/Host 验证用户输入仅经一次受控传递，预览开关和清除行为正确，stderr/stdout 不包含测试文本；保留状态桥接及发布 Helper 回归。

## 范围

本期不实现对话历史、完整迷你聊天、多会话切换快捷菜单、自动选择最近会话、新建会话、模型/权限配置、工具结果展示、语音或网络端口。DSH 继续是会话、模型、持久化与恢复的唯一所有者；WPF Helper 只提供短暂输入与可选预览界面。
