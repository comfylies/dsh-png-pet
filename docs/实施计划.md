# DSH PNG 桌宠：Windows MVP 实施计划

## 阶段 0：DSH 插件与 C# Helper 骨架 ✅ 已完成

**完成情况：** 已实现并验证 DSH npm 插件骨架、TypeScript Helper 生命周期、JSON Lines `ready`/`shutdown`/`closed` 握手、.NET 10 Windows x64 自包含 WPF Helper、npm 打包和 DSH `web` profile 安装。当前发布版本为 `dsh-png-pet@0.1.1`。

目标：建立可由 DSH 加载、能启动和关闭 Windows Helper 的发布骨架，不实现桌宠行为。

- [x] 创建 ESM TypeScript npm 包，声明 DSH `web` profile 的 bundle patch、Host 入口和插件名称。
- [x] 创建 `pet-helper` C# WPF 项目，目标为 .NET 10 Windows，并配置为 Windows x64 自包含发布。
- [x] 定义并实现最小 JSON Lines 协议：`hello`、`ready`、`config`、`state`、`shutdown`、`closed`。
- [x] 实现 TypeScript `HelperProcess`：解析包内 `runtime/bin/win32-x64/pet-helper.exe`，启动子进程、写入 stdin、按行读取 stdout，并在退出时清理资源。
- [x] 实现 WPF Helper 的最小协议循环：启动即输出 `ready`；收到 `shutdown` 后输出 `closed` 并退出。
- [x] 将自包含 Helper 发布产物复制至 npm 包的 `runtime/bin/win32-x64/`；确保 `package.json` 的 `files` 包含运行时、资产和文档。

验收：将 `.tgz` 安装到 DSH `web` profile 后，DSH 启动能拉起 Helper，DSH 退出能在有限时间内关闭 Helper；终端用户不需单独安装 .NET。

## 阶段 1：协议、状态归约与 DSH 事件观察 ⏭️ 下一阶段

目标：桌宠状态只来源于 DSH 的真实事件，且绝不干扰 DSH 的 Agent 流程。

1. 为协议消息建立运行时校验：协议版本、消息种类、状态枚举、长度上限和未知字段处理策略。
2. 实现 `CompanionReducer`，将 `session/event` 和 `session/disposed` 转为每个 Session 的 `idle`、`thinking`、`working`、`waiting`、`success`、`error` 状态。
3. 为每个状态转换保留最近一次事件序号，忽略过期、重复和已释放 Session 的事件。
4. 实现顶层 Session 优先级：`waiting > error > working > thinking > success > idle`；默认忽略子 Agent，配置开启后再纳入。
5. 在 DSH 插件入口注册全局 `session/event` 与 `session/disposed` 观察器；每个回调使用错误边界，任何插件异常只写脱敏诊断，不能向 DSH 事件总线抛出。
6. 将归约后的状态、阶段和结构化待办摘要发送给 Helper；没有结构化待办时只发送阶段，不计算百分比。

验收：使用受控 Session 事件测试状态转换、乱序事件、Session 释放、多 Session 优先级和子 Agent 开关；错误的事件载荷不会中断 DSH 或影响其他插件。

## 阶段 2：WPF 透明桌宠与 PNG 动画 🟡 部分完成

**已完成部分：** 透明无边框窗口、置顶、拖拽、位置保存、缩放、右键菜单、系统托盘、显示/隐藏、重置和退出，以及透明 PNG 资源替换。**尚未完成：** 状态 manifest、七种状态动画、状态气泡、减少动态效果和多显示器位置校正。

目标：实现唯一可见的本机界面，不引入网页前端。

1. 定义 `pet-manifest.json`：每个状态列出 PNG 帧、帧间隔、是否循环、成功/错误停留时长和减少动态效果下的静态帧。
2. 创建或导入许可明确的透明 PNG 资产：idle、thinking、working、waiting、success、error、disconnected。
3. 使用 WPF 无边框透明窗口实现 PNG 帧播放器，按状态切换动作，成功动画只播放一次并等待下一条状态消息。
4. 实现气泡控件，只显示插件明确发送的阶段、待办摘要或错误类别；限制文本长度，不渲染模型回复、提示词或工具参数。
5. 实现拖拽和位置存储；Helper 启动时按当前多显示器工作区校正越界位置。
6. 实现减少动态效果：状态动画改为静态帧或低频更新，不改变状态含义。

验收：在无 DSH 网络请求的 Helper 协议测试中，七种状态均可见、窗口透明无边框、拖拽可用、位置重启后仍在可见屏幕范围内；减少动态效果生效。

## 阶段 3：DSH 配置、托盘和生命周期管理 🟡 部分完成

**已完成部分：** Helper 的本机托盘菜单（显示、退出）和 DSH 停止时的基础 Helper 关闭路径。**尚未完成：** DSH 设置持久化、菜单回传、打开 DSH、本次关闭抑制重启、崩溃退避重启和完整插件生命周期验证。

目标：让用户可不打开 WebUI 而日常使用桌宠，并让 Helper 严格隶属于 DSH 生命周期。

1. 使用 DSH 设置服务注册并持久化：`enabled`、`scale`、`reducedMotion`、`includeSubagents`。
2. 实现设置热更新：缩放、减少动态效果和子 Agent 开关通过 `config` 消息实时应用，不重启 Helper；`enabled=false` 时有序关闭 Helper，重新启用时防抖启动。
3. 在 Helper 实现系统托盘和右键菜单：显示/隐藏、大小档位、减少动态效果、打开 DSH、本次关闭。
4. 将大小与减少动态效果的菜单操作回传插件，由插件更新 DSH 设置服务；显示/隐藏与本次关闭只保留为 Helper 运行期状态。
5. 实现“打开 DSH”回调：仅在用户明确点击后调用由插件提供的本机 WebUI 地址；插件启动时绝不触发浏览器打开。
6. 实现关闭策略：DSH 停止、插件卸载或禁用时先发送 `shutdown`，等待确认后关闭子进程；Helper 意外崩溃时有限次数指数退避重启；本次关闭不重启。

验收：运行 `dsh web --no-open` 后仅显示桌宠；所有托盘菜单可用；配置变更即时生效；DSH 退出、插件禁用和本次关闭均符合预期，且无孤儿 Helper。

3. 编写插件集成测试：模拟 DSH 事件流，验证 Helper 收到正确消息；模拟 Helper 提前退出、拒绝协议、无响应关闭和重复 `ready`。
4. 进行人工验收：无活动、思考、工具工作、等待确认、完成、错误、多 Session、子 Agent、隐藏/显示、DPI 变化、多显示器、DSH 重启和插件更新。

验收：自动化测试通过；人工验收覆盖全部 MVP 场景；隐私审查无敏感数据；Helper 在异常和正常退出路径都不会遗留进程。

## 技术边界

```text
TypeScript / Node.js：DSH 插件入口、事件观察、状态归约、设置、Helper 生命周期
C# / WPF / .NET 10：透明桌宠、PNG 动画、气泡、拖拽、托盘、位置保存
stdin/stdout JSON Lines：唯一的插件与 Helper 通信通道
DSH：Agent、Session、模型、凭据、WebUI 与插件安装生命周期
```

- TypeScript 插件不读取或传递模型 API Key，也不直接调用模型服务。
- C# Helper 不连接网络、不读取 DSH 文件或 Session，也不承担 Agent 逻辑。
- Helper 不实现独立聊天、设置 WebUI 或新的 HTTP 服务；DSH WebUI 仅按用户明确操作打开。
- 不为 Linux、macOS、WSL2 或独立桌面应用保留兼容层；Windows-only 范围保持明确。
